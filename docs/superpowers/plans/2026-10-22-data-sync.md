# Data sync preparation implementation plan

> Execute inline with superpowers:executing-plans. User approved framework and integration preparation without provider accounts. Do not activate schedules, push commits, or deploy.

**Goal:** Validate normalized event/ranking feeds, preserve good data on failure, publish versioned snapshots consumed by the existing app, and honestly display freshness.

**Architecture:** Keep the bundled archive as baseline. A Node ingestion command validates all input before atomically replacing one snapshot JSON. Event additions are append-only and conflicts require review. Ranking editions are immutable and retained. Build-time imports keep search, map, comparison, and statistics consistent. A disabled-by-default CI schedule prepares validated updates; external feed adapters and deployment activation remain explicit integration steps.

**Stack:** TypeScript, Zod, Node tests, existing React/Vite pipeline, GitHub Actions.

- [ ] Define strict feed/snapshot schemas and merge rules; test rejection of unfinished/future events, duplicates, conflicting identities, unknown cities, stale rankings and unsafe source links.
- [ ] Implement bounded fetch/local-input ingestion, secret-safe errors, atomic write, and version history. Test failure leaves previous file intact.
- [ ] Wire validated snapshots into existing event/ranking exports and dynamic year bounds; add visible source/freshness status without claiming live sync.
- [ ] Add gated schedule configuration and integration documentation. No external provider adapter is claimed complete.
- [ ] Run tests, typecheck, production build, desktop/mobile smoke, browser interactions and independent review.
